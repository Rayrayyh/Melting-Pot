# The sidebar folds, and the controls are ours

Chosen 2026-09-02 by the owner, from a screenshot of a blue system menu on the cream search page and a recording of kolejain.com's sidebar.

Four changes with one theme: the parts of the app the browser used to draw now draw themselves.

**The sidebar collapses.** One control under the wordmark narrows it from 240px to 72px over a second on the long ease out kolejain.com uses, cubic-bezier(0.075, 0.82, 0.165, 1). Labels are clipped by the moving edge rather than faded, because the clip is what makes the fold read as a fold. Rows recentre on their icons, and anything that only makes sense at full width (shortcut hints, the Pots list, the profile text) is hidden. The choice lives in localStorage and is stamped on the html element by the same inline script that stamps the theme, so a collapsed sidebar never flashes wide on reload. The notification card pops out the moment the fold starts and pops back in only after the width has settled; the same pop plays when it is dismissed. Its collapse hook sits on the card itself rather than on the animated wrapper, because the wrapper carries an inline opacity from its enter animation that beats any stylesheet rule.

**The My Pots list remembers itself across sidebars.** Every page renders its own shell, so every navigation mounts a fresh nav, and the list used to reappear already closed: a cut, where every other close was a slide. The last state now lives in module scope, and a route change that crosses the Pot boundary slides the list two frames after the new nav has painted the old state. Cold navigations still pass through the route loader, where the whole shell is replaced, and there is no list on screen to animate.

**The select is ours.** A native select paints its list in the operating system's style, and a warm paper page grew a blue Windows menu the moment anyone sorted it. `web/components/ui/select.tsx` is the account menu from the foot of the sidebar, generalised: the same raised card, the same rows, the same short rise on open, with a check against the current choice, full keyboard reach (arrows, Home, End, type-ahead, Enter, Escape) and the listbox pattern for assistive tech. The three native selects (the search Pot filter, the search sort and the contribution section picker) use it, and the account menu itself now rises and settles on the same curve so there is one dropdown motion in the product.

**Notification rows and the scrollbar.** A row under the pointer lifts onto the card's surface, an orange hairline draws up its left edge, the icon tips towards the title, the title steps right and an arrow arrives at the end; all of it rides the sidebar's ease and stills under reduced motion. The scrollbar is drawn where the browser allows it: a slim pill in the paper's tan in a clear gutter, no track, no arrow buttons, fuller under the pointer and brand orange while dragged. Chromium ignores the `::-webkit-scrollbar` rules the moment `scrollbar-color` is set, so the standard properties are reserved for browsers without the pseudo-elements, which today means Firefox and a thin tinted bar.

Rejected along the way: fading the labels on collapse, a separate motion for the account menu, and a ring around the open list when the highlighted row already shows where focus is.
